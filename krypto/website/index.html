Was Kairn ist

Ein Token ohne Hintertür

Kairn ist ein gewöhnlicher ERC-20-Token mit vier Zusätzen. Der Vertrag hat keinen Besitzer und keine Pausentaste und lässt sich nicht upgraden. Was beim Start festgelegt wird, gilt für immer.

Zahlen per Signatur

Ein Agent signiert eine Zahlung, der Dienst reicht sie ein und bezahlt das Gas. Der Agent braucht also kein ETH, nur KAIRN. Auch Smart-Contract-Wallets können signieren.

EIP-3009 · ERC-1271

Feste Menge

Beim Start entstehen genau 1 000 000 000 KAIRN. Eine Mint-Funktion gibt es nicht. Wer Token vernichtet (burn), senkt die Menge dauerhaft.

ERC-20 · Burnable

Stimmrecht

Jeder Token ist eine Stimme für die Kairn-DAO. Die Stimmen zählen nach Zeitstempel. Das ist auf Layer-2-Chains wie Base verlässlicher als die Blocknummer.

ERC20Votes · mode=timestamp

Freigabe ohne Gas

Freigaben an Apps und Börsen (approve) lassen sich ebenfalls per Signatur erteilen. Eine eigene Transaktion ist dafür nicht nötig.

EIP-2612 · Permit
Agenten-Zahlungen

HTTP 402 wird endlich benutzt

Den Statuscode 402 „Payment Required“ gibt es seit 1997. Mit x402 erhält er eine Bedeutung: Der Server nennt einen Preis, und der Agent bezahlt mit einer signierten Autorisierung. Kairn unterstützt genau das Verfahren, das x402 auf EVM-Chains verwendet.

Anfrage

Der Agent ruft eine kostenpflichtige API auf, zum Beispiel GET /wetter/zermatt.

Preis

Der Server antwortet mit 402. Die Antwort nennt Betrag, Empfänger und Token.

Signatur

Der Agent signiert TransferWithAuthorization. Dafür braucht er weder ETH noch eine Transaktion.

Abrechnung

Der Server reicht die Signatur on-chain ein, zahlt das Gas und liefert die Daten.

HTTP/1.1 402 Payment Required content-type: application/json { "scheme": "exact", "network": "base", "asset": "KAIRN", "maxAmountRequired": "0.02", "payTo": "0x…Dienst", "maxTimeoutSeconds": 60 }

Kairn DAO

Das Treasury gehört der DAO

Das Treasury umfasst 600 Mio. KAIRN und liegt in einem Timelock-Vertrag. Auszahlungen gibt es nur per Abstimmung, zum Beispiel als Grants für Entwicklerinnen und Entwickler von Agenten. Nach dem Deployment hat das Gründungsteam keinen Zugriff mehr.

Community-Airdrop

Den eigenen Anteil holen

20 % der Menge gehen an frühe Nutzerinnen und Nutzer. Dafür gibt es keinen Verkauf und keine Registrierung. Wer auf der Liste steht, holt seine Token innerhalb von 180 Tagen ab. Danach fällt der Rest an das DAO-Treasury.

Etappen

Die Route

Kairn geht erst live, wenn der Code geprüft ist und die rechtliche Einordnung steht.

Etappe 1 erledigt

Verträge und Tests

Token, DAO, Vesting und Airdrop sind fertig und durch 31 automatische Tests abgedeckt (100 % der Codezeilen).

Etappe 2 als Nächstes

Testnetz Base Sepolia

Öffentlicher Probebetrieb mit einem Bug-Bounty-Programm und einer Beispiel-API, die per x402 abrechnet.

Etappe 3

Audit und Recht

Unabhängige Prüfung des Codes, Einordnung durch die FINMA und Aufsetzen der Multisig-Wallets.

Etappe 4

Launch auf Base

Deployment, Airdrop-Start und Liquiditätspool. Danach übernimmt die DAO.

Fragen

Häufige Fragen

Kann ich KAIRN kaufen?

Bei Kairn gibt es weder Vorverkauf noch ICO. Nach dem Launch stellt die Liquiditäts-Zuteilung einen Pool auf einer dezentralen Börse bereit.

Wer kontrolliert den Vertrag?

Niemand. Der Token-Vertrag hat keinen Owner. Das Treasury verwaltet ausschliesslich die DAO, und der Deployer gibt seine Admin-Rechte schon beim Deployment ab.

Warum Base?

Transaktionen kosten auf Base Bruchteile eines Rappens. Viele x402-Dienste laufen bereits dort, und die Coinbase-Wallet ist direkt angebunden.

Was passiert mit nicht abgeholten Airdrop-Token?

Nach 180 Tagen kann jede Person die Funktion sweep() aufrufen. Der Rest geht dann an das DAO-Treasury und nicht an das Team.
